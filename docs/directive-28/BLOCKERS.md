# Directive 28 blockers and required human actions

These blockers replace the deployment blockers in
[../overnight/BLOCKERS.md](../overnight/BLOCKERS.md). With the dedicated
project decision, several overnight blockers disappear: the occupied default
site, the shared bucket, Enterprise edition vs the emulator, and the legacy
client sharing the database.

## Critical blockers (deployment is not allowed until resolved)

| # | Blocker | Evidence | Resolved by |
|---|---|---|---|
| C1 | **`v-nexus-lite` cannot isolate DSBC** (shared Auth pool, editor-level default runtime identity, no DSBC bucket, shared web app) | ENVIRONMENT-AUDIT §3; probe PROJECT_BOUNDARY, FUNCTIONS_IDENTITY, STORAGE_BUCKET, AUTH_EMAIL_PROVIDER = BLOCKED | a dedicated DSBC project (H1) |
| C2 | **No dedicated DSBC project exists** that the operator can use | `command-centre-640ac` hosts another app; `dsbc-e8ok3g3sf` is inaccessible (403) and its purpose is unknown | H1 |
| C3 | **No App Owner identity designated** | AUTHORITY-PLAN | H4 |
| C4 | **No email-verification flow**, so no account can satisfy the App Owner's `email_verified` requirement through the DSBC UI | `sendEmailVerification` absent from `src/` | next directive (code) |
| C5 | **No public domain chosen** (QR codes depend on it) | HOSTING-PLAN | H3 |
| C6 | **Function secrets** must exist before functions deploy | the webhook declares 2 secrets | H5 |
